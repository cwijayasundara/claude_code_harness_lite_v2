# sdlc v0.3: superpowers SDD for large builds, a deep wiki, fixes and a lean guard

Status: approved in conversation on 2026-10-03 · branch `v0.3` · target: built and live-trialled the same day.

## 1. Intent

**What the person said.** The aim is one harness the whole company can use, from a junior engineer to an SVP. It should be lean and clean, token-efficient and fast, and it should produce well-tested, performant code. superpowers subagent-driven development (SDD) becomes the build engine inside the harness (option A). Every issue from the 2026-10-03 review gets fixed, including the deep wiki. **The harness stays under 5,000 lines.** Approved trade-offs: the evidence guard is simplified, and a paid three-arm trial runs today (about $10–15).

**Success criteria**
1. The LOC test passes: everything except tests and docs is at most 5,000 lines.
2. All unit tests, mod tests and both typechecks pass.
3. In the live tier L trial, the harness with SDD and the harness with its native build both pass the hidden acceptance test, and neither has the empty-key auth bypass.
4. The trial reports cost, wall time and an Opus split (architect / reviewer / advisor) for each arm.
5. Tier S and M paths behave as before. This is checked by the existing tests; there is no new cost on those paths.

**Non-goals**
- Jira or Linear integration.
- Mockups.
- Deploying to a test environment.
- A Claude Code version check.
- Reformatting existing long lines, beyond lines the change touches.
- Changing model routing before trial data exists. Routing changes follow §9 only.

## 2. LOC budget

`scripts/size.spec.ts` gains a test that sums the lines of every file except tests and docs:
- `scripts/*.ts` (excluding `*.spec.ts` and `testkit.ts`)
- `hooks/*`
- `skills/*/SKILL.md`, `agents/*.md`, `guides/*.md`
- `templates/*`
- `.github/workflows/*`
- `.claude-plugin/*.json`, `package.json`

The test fails above 5,000. The existing per-file test for mod files also covers `.ts`; it filters on `.tsx` only, so the renamed `register.ts` and `gates.ts` currently escape it. Baseline: 3,796.

## 3. superpowers SDD as the build engine (tier L and greenfield)

**Plan format (architect).** The architect writes slices as `### Task N: <name>` headings under `## Slices`, because SDD's `task-brief` extracts tasks by that heading. It also adds `## Global Constraints`: binding values, guides that apply, and the rule that red runs go through `sdlc.ts run --expect-fail`. Both still serve sdlc's native path. The no-code rule is unchanged: interfaces and test cases only.

**Build skill.**
- **Small builds** (inline): unchanged.
- **Tier M large builds:** native orchestration, unchanged.
- **Tier L and greenfield, when `superpowers:subagent-driven-development` is in the available skills** (otherwise native orchestration): first `git checkout -b sdlc/<slug>` if on main. Then invoke `superpowers:subagent-driven-development` on `.sdlc/changes/<slug>/plan.md` with these caller overrides (superpowers ranks caller instructions above its skills):
  - Work in the current tree on `sdlc/<slug>`. No `using-git-worktrees`, so `.sdlc/` evidence and baselines stay in one tree.
  - Implementers and task reviewers run on Sonnet (`model: sonnet`). Rounds 4–5 never happen.
  - **At most 1 fix round per task.** Findings still open afterwards are recorded in the SDD ledger, and the build continues. sdlc's review sees them.
  - Implementers run red tests through `sdlc.ts run --expect-fail` and stay inside the task's files.
  - **Skip** SDD's final whole-branch review and `finishing-a-development-branch`. When every task is complete, return to sdlc with `Next: /sdlc:verify <slug>`.
- **Fallback.** `hookSkillFailed` also matches `superpowers:subagent-driven-development`. Its context tells the model to continue with the build skill's native orchestration section, and the failure is logged as `skill-load-failed`.

**Routing guard.** With superpowers enabled, its session-start text pushes brainstorming onto every creative task. Two things prevent that:
- Onboard writes this line into CLAUDE.md: `sdlc routes all work in this repo: start with /sdlc:start; use superpowers skills only when an sdlc skill names one.` CLAUDE.md is a user instruction, which superpowers ranks above itself.
- Session-start context repeats the line.

**Settings template.** `superpowers@claude-plugins-official: true`. The README states 6.4.1 or later.

**Compatibility.** SDD commits per task. Ship already commits whatever remains: the `.sdlc/` artifacts always do. Scope drift, red-proof and traceability judge the branch diff against the base, so per-task commits are fine.

## 4. Fixes

- **F1: STATE.md contradiction.** `setActive(slug)` replaces the body when it is the init template (`No active change.`) or a `clearState` body, writing `# State\n\nActive change: <slug>. Next: see /sdlc-status.\n`. A body the model wrote is kept.
- **F2: tier L bugfix and incident gate.**
  - `PATHS.bugfix` and `PATHS.incident` become `intent → plan → diagnose → verify → review → ship`. `plan` is filtered out unless the tier is L.
  - For these types, `nextCommand` maps the `plan` stage to `/sdlc:diagnose <slug>`.
  - The diagnose skill, at tier L: reproduce and isolate, then write `plan.md` (root cause, `## Files`, `## Verification`, no code), then stop with the approval command. On the next run it applies the fix.
  - `GATES.L` already holds `plan`. A bugfix has no spec stage, so `spec` in `GATES.L` is inert for it.
- **F3: line length.**
  - `limits.lineChars`: default 160, validated like the other limits.
  - The size sensor warns on each added line over the limit in source files at stop, ship and ci, and adds a summary count for diffs.
  - This repo's `.sdlc/sensors.json` sets 160.
- **F4: the mod-file size test covers `.ts`** (see §2).

## 5. Evidence guard: frozen and simplified

**The trust boundary is CI.** The base-branch checker reruns the `full` commands, CODEOWNERS covers `.sdlc/**`, and `humanRowsAdded` lists every approval and waiver row a PR adds. The local guard is best-effort and stops at one rule.

**Bash (pre-bash).**
- Deny when the command names `sdlc.ts approve|waive`.
- Otherwise deny when it names an evidence path or evidence file name, unless every segment that names one is one of:
  - git `add|commit|status|diff|log|show` without `--output`
  - `cat|head|tail|wc|grep|rg|jq` with no `>` redirect

**Removed:**
- `globWrite`
- `linksIntoSdlc`
- `dequoted` and the double raw/dequoted checks
- the hard-link inode check in `isEvidenceFile`
- the `SDLC_HUMAN` regex

**Kept:**
- The Edit/Write real-path check, which is cheap and exact.
- The read-only agent allowlist (`shell.ts` `readOnlyDenial`). It is a scoping aid for scout, reviewer and verifier, not a forgery guard, so it stays.
- `tokenize`, where `readOnlyDenial` uses it.

**Tests.** Forgery tests for removed rules are deleted. A test pins the documented gap: a quoted or obfuscated write is not blocked locally, and the CI check still reports the added row. The DESIGN.md §2 principle 8 note says: local guard best-effort, CI decides.

## 6. Test layers (no new code)

- `full` already takes named commands, so `smoke`, `e2e` and `bench` are conventions only.
- **Onboard** detects them (a Playwright config, `start` and health scripts, a bench script) or asks once. It writes them into `full` and says what each one proves.
- **testing.md guide** gains three short rules:
  - API tests hit the real HTTP surface and assert on status and body.
  - Smoke tests start the app, hit a health check, then stop it, with a timeout.
  - A bench command exits non-zero when it misses its threshold, and the threshold is written in the spec's `## Non-functional`.
- The architect lists these in `## Verification` when the spec has a matching NFR or UI.

## 7. Deep wiki (`docs/wiki/`)

**Layout.** Committed markdown that renders on GitHub without Claude:
- `index.md`: what the system is, a Mermaid module map, and a table of modules.
- `modules/<name>.md`, one per module: purpose, key files as `path:line`, entry points, data flow, contracts, tests, and `## Recent changes` (one line per shipped slug, newest first, at most 10).
- `manifest.json`: `{ "pages": { "modules/<name>.md": { "globs": [...], "surface": "<sha16>" } } }`.

**Surface hash.** sha256 of the sorted matched file list plus every line, in those files, matching the public-surface regex:

```
^\s*(export|pub |def |class |func |public |interface |type |module\.exports)
```

Edits inside function bodies do not make a page stale.

**Script (`sdlc.ts wiki`).**
- `wiki status [--json]` lists pages whose surface changed, globs that match nothing, and top-level source directories no page covers. It is pure and has no model calls.
- `wiki stamp [page...]` recomputes and stores hashes for the named pages, or for all pages. It sanctions the manifest write.

**Sensor `wiki-stale`.**
- Warn only, at ship and ci, when `docs/wiki/manifest.json` exists. It reports stale and uncovered pages.
- It is added to `SENSOR_NAMES`.
- It runs on the branch head, not the diff, so it costs no tokens.

**Agent `wiki`.** Sonnet, `effort: low`, `maxTurns: 25`.
- Tools: Read, Grep, Glob, LSP, Write, Edit (writes only under `docs/wiki/`).
- Input: page path, globs, scout facts or the diff, and the old page.
- Output: the page, at most 120 lines, every claim cited as `path:line`.

**Skill `/sdlc:wiki [--update]`.**
- **Full build:**
  1. Group the source into at most 12 modules from the onboard map (or one scout).
  2. Launch at most 3 `wiki` agents per message, in parallel.
  3. Write `index.md` and the manifest.
  4. Run `wiki stamp`.
- **Update:** rewrite only the pages `wiki status` lists, add the shipped slug to `## Recent changes`, then stamp.

**Hooks into the flow.**
- **Onboard (brownfield)** runs the full build after CLAUDE.md, reusing scout (a)'s module map.
- **Ship skill:** before `sdlc.ts ship`, if `wiki status` reports stale pages, run the update. `cmdShip` stages `docs/wiki/**` as harness-owned, not as scope drift.
- **The scout agent** reads `docs/wiki/index.md` first when it exists.
- **Session start:** when source exists and `docs/wiki/` does not, add one line: `No code wiki yet: /sdlc:wiki builds it.`

**Expected cost.** Full build: one scout plus about 12 Sonnet low-effort agents. Update: one Sonnet low-effort agent per stale page. Both are measured in the trial (§9).

## 8. Junior-proofing

- **`/sdlc:next`** (skill, about 20 lines):
  1. Run `sdlc.ts status --json`.
  2. If the next step is a human gate, print the exact approval command and stop.
  3. Otherwise run `sdlc.ts skill <stage> <slug>` and follow the printed steps inline. It never uses the Skill tool for chaining, because that failed in `-p`.
  4. If nothing is active, ask what to build and follow `/sdlc:start`.
- **README "Team install":** add the repo as a git marketplace (`/plugin marketplace add <git url>`), pin by tag, enable through a shared project `.claude/settings.json`, and use `/sdlc:next` when unsure. The README's "Use" table leads with `/sdlc:start` and `/sdlc:next`.

## 9. Live trial (paid, about $10–15)

**Task.** Tier L on todo-core:
- API-key auth: `x-api-key` header, users from config.
- Per-user isolation of todos.
- Pagination: `?limit&offset`, capped at 100.
- Atomic file store: write to a temp file, then rename.

**Hidden acceptance test.** `tests/trials/acceptance-L.test.js` checks:
- 401 without a key or with a wrong key
- no isolation leak between users
- pagination bounds
- the store survives a mid-write crash simulation
- **an empty `apiKey` with an empty header must not authenticate**

**Arms.** Run in parallel in fresh copies by `tests/trials/run-trials.sh L [outdir]`:
1. Plain Claude Code.
2. Harness with native build (superpowers disabled in the trial repo's `.claude/settings.json`, so the skill is not listed).
3. Harness with SDD build (superpowers enabled).

Gates are approved by the script, as in the existing runner.

**Report.** Per arm: cost, turns, wall time, acceptance results, Stop blocks, skill fallbacks, review findings caught, and an Opus split.
- The split comes from `tests/trials/split.mjs`, which reads the session transcripts (`~/.claude/projects/<dir>/*.jsonl` including subagent sidechains). It sums cost by agent type and model. Advisor cost is main-thread Opus.
- The wiki build cost is measured once on arm 2's repo after ship.

**Routing decision after the trial**, recorded in DESIGN.md:
- If the architect dominates Opus spend on L and the architect's plan quality isn't what caught defects, move tier M plans to Sonnet.
- If SDD costs more than 1.5× native for no acceptance or defect gain, keep native as the default and leave SDD opt-in (`sensors.json` `"build": "sdd"`).
  - **Implementing that switch is out of scope today.** The trial result decides only the default named in the build skill.

## 11. Risks

- **superpowers updates may change SDD's plan contract** (the `Task N` heading). The fallback keeps builds working. The README pins the minimum version.
- **SDD's "rulings, not stalls" stance could skip a human question.** sdlc's gates come before build (plan approval) and after it (review and ship), so a wrong ruling is caught at review.
- **A weaker local guard.** The trade is accepted and documented in §5.
