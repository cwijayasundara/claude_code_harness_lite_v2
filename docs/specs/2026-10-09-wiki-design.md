# rig-util: wiki module design

Date: 2026-10-09. Status: draft for review.

## 1. Purpose

Agents write code faster than people can follow it. `rig-util` is an optional Claude Code plugin that sits beside the
`rig` harness (it is not part of rig core). Its first module, `wiki`, keeps a DeepWiki-style set of markdown pages
about a target repo, up to date with the code, so human developers can understand agent-written code and so Claude can
look there before it greps. A second module, `rsi` (a self-improvement loop in the style of Cognition's agent-memory
repo), is out of scope here and gets its own spec.

Success criteria:
- A developer opens the wiki (GitHub, an editor, or Obsidian's graph view, no server) and finds what each module is for,
  its public API, what depends on it, and which rig change made it the way it is.
- After a code change the wiki shows which pages are stale within one turn, and a refresh rewrites only those.
- Claude finds the right files with fewer Glob/Grep calls than without the wiki (measured by an eval; if not, the
  agent-facing injection is dropped).
- `npm test` runs with no model calls. Hooks never call a model and never block a turn.

## 2. Boundaries

- Separate repo `learning_101/rig-util`, installed as a plugin from its own marketplace. rig core knows nothing about it.
- Integration with rig is through files and the CLI only: read `.sdlc/changes/*`, `.sdlc/sensors.json` (`scopes`,
  `ignore`), `.sdlc/bin/VERSION`; never import rig's `scripts/*.ts`. If a rig event is ever needed, it is proposed to
  core as a small documented hook, not as wiki logic.
- Works without rig changes present (the "Why" section is then omitted) and without rig installed (no `scopes`, defaults used).
- v1 languages: TypeScript and JavaScript with symbol-level accuracy. Everything else is structure only.

## 3. Repository layout

```
rig-util/
  .claude-plugin/{plugin.json,marketplace.json}
  hooks/hooks.json            # mark-stale only, no model calls
  skills/wiki-refresh/ skills/wiki-find/
  agents/wiki-writer.md       # Haiku for facts, Sonnet for narrative
  scripts/                    # indexer, hashing, planner, index builder, swap/validate
  contract/                   # fixture .sdlc trees per supported rig version
  tests/
  docs/specs/
```

Target repo output, committed:

```
.sdlc/wiki/
  INDEX.md                    # compact agent map, stale marks
  architecture.md
  modules/<name>.md
  .state.json                 # hashes and page-to-file map
  .cache/                     # gitignored: index.json, temp pages
.sdlc/wiki.json               # optional config: module globs, caps
```

## 4. Pipeline

1. **Mark stale (hook, no model).** `PostToolUse` on Write/Edit/MultiEdit and `Stop` compare content hashes against
   `.state.json` and set affected pages to `stale`. Budget 15s; failure logs and never blocks.
2. **Index (deterministic).** The indexer writes `.cache/index.json`: modules, files, exported symbols with signatures,
   imports and re-exports, first doc comments, edges. Writers see only this file, never the raw repo.
3. **Plan (deterministic).** Diff `index.json` against `.state.json`. A function-body change marks only its module stale.
   A signature change also marks importers stale, limited to their "uses" section. Output: ordered page list, capped.
4. **Write.** Facts sections are generated by code. Purpose, How it works and Why are written by `wiki-writer`
   (Haiku for facts-adjacent summaries, one Sonnet pass for narrative and Mermaid for changed pages).
5. **Validate and swap.** Pages go to a temp dir; frontmatter, relative links and Mermaid are checked; then swapped in.
   A failed page leaves the previous version.
6. **Rebuild `INDEX.md`** deterministically.

Triggers: the mark-stale hooks every turn; `wiki-refresh` on demand; the PR step of a rig change; a CI workflow
(stale pages produce a warning, not a failure).

## 5. Indexer and modules

- TS/JS via the TypeScript compiler API. Fallback for other languages: file tree, regex imports (Python, Go, Java),
  file-level hashes; pages are marked `structure-only`.
- Default module = top-level directory under `src/`, `scripts/`, `packages/*`. Overrides in `.sdlc/wiki.json`
  (glob to module name). rig's `scopes` are reused when present.
- A module hash covers file contents and exported signatures.
- Honors `.gitignore` and rig's `ignore`; skips `node_modules`, build output and files matching rig's secret patterns,
  so these never reach a model.

## 6. Page format

```markdown
---
module: auth
files: [src/auth/*.ts]
hash: 9c1f...
generated: 2026-10-09
status: fresh | stale | structure-only
changes: [add-sso, fix-token-expiry]
---
# auth
Purpose (2-3 sentences). Public API (table). Depends on / Used by (relative links).
How it works (short narrative, one Mermaid diagram if it earns it).
Why it is this way (rig change slug, one-line intent, link to .sdlc/changes/<slug>/).
```

- API, Depends on and Used by are deterministic. Purpose, How it works and Why involve a model.
- "Why" is built from `intent.md` and `design.md` of changes whose diffs touched the module.
- Content between `<!-- keep -->` markers survives regeneration; a page whose rewrite would drop a kept block fails
  validation and keeps its old version.
- Links are standard relative markdown links (render on GitHub and in Obsidian's graph view). No `[[wikilinks]]`.
- `architecture.md`: Mermaid module graph from the index plus a short narrative.

## 7. Agent-facing use

- `INDEX.md`: one line per module (name, purpose first sentence, key files and top symbols, stale mark), capped near
  2k tokens; large repos rank by dependents and recent change, the rest listed by name.
- Injection: `SessionStart` prints the index path and a one-line instruction; first touch injects the index once per
  session. The repo's CLAUDE.md gets one line pointing at it.
- `wiki-find <term or question>`: ranks pages and symbols from `index.json` by token match on names, paths and purpose
  (no embeddings in v1). Returns files, symbols, page links and stale flags. Results are pointers; Claude verifies in code.
- Eval: paired `.sdlc/evals/` runs with and without the index, counting Glob/Grep calls, tokens and correctness. If
  the index does not cut search cost on a real repo, injection is removed and the wiki stays for humans.

## 8. Failure handling

- No model calls in hooks; 15s budget; hook failures log only.
- Stale pages keep old content with `status: stale` and a banner. Staleness is never hidden.
- Per-run cap of 25 pages (configurable) and a model-call budget; overflow is reported as pending, highest priority first.
- Temp-dir-and-swap writes; no partially written pages.

## 9. Testing

- Unit specs for indexer, hashing and planner on fixture repos; golden files for deterministic sections and `INDEX.md`.
- `contract/` fixtures: the plugin reads `.sdlc` trees from each supported rig version; runtime check of
  `.sdlc/bin/VERSION`.
- The writer is stubbed in unit tests. One opt-in live e2e runs the pipeline on a small fixture repo.
- `npm test` makes no model calls.

## 10. Out of scope for v1

The `rsi` module, a `graph.html` viewer, embedding or semantic search, non-JS/TS symbol extraction, a hosted site.

## 11. Open decisions for the plan

- Exact CLI shape of `scripts/` (single `wiki.ts <cmd>` mirroring rig's `sdlc.ts`, recommended).
- Whether the first-touch injection is a `UserPromptSubmit` or a `PreToolUse(Glob|Grep)` hook; decided by the eval.
- Minimum supported rig version for `contract/`.
